## Project: BEmmy — Emmy in the Browser

A static-page Clojure(Script) playground for SICM. Scittle hosts SCI in a
`<script>` tag; a custom Scittle plugin registers Emmy + mafs.cljs +
mathbox.cljs + leva.cljs + the 2D portion of emmy-viewers. CodeMirror 6
editor, multi-page localStorage, system-page templates with copy-on-edit
forking, scmutils-Scheme → Emmy translator shelf, KaTeX-rendered Emmy
expressions, 2D plots (`plot`, `plot-with-params`, `animate`, frame-based
SICM-book imperative graphics shim) and 3D plots (MathBox via Three.js
pinned to 0.139.2), share-by-URL.

## Layout

- `public/` — static deploy target (drop into any static host).
  - `index.html`, `app.cljs` (Scittle-evaluated), `sicm2emmy.js`
    (Scheme→Clojure translator), pshift logo bundle.
  - `js/` — built plugin bundle (`scittle.emmy.js` + scittle stock).
    Regenerated by `bb release`. Gitignored.
  - `vendor/` — static CDN deps copied locally (KaTeX + 20 woff2 fonts,
    Mafs core.css, hljs, React UMD, CodeMirror 6 + transitive deps).
    Tracked.
- `src/scittle/emmy.cljs` + `src/scittle_plugin.edn` — plugin source +
  manifest fed to scittle.build.
- `test/sicm2emmy.test.js` — node:test suite for the translator.
- `bb.edn` — `bb release` (build), `bb serve` (http-server on :1341),
  `bb dev` (watch + serve), `bb test` (translator tests).
- `bin/vendor.sh` — re-run to refresh `public/vendor/` static deps.
  Invokes `bin/vendor-cm.mjs` for the CodeMirror dep-graph walk.

## Test/verify loop

Automated: `bb test` runs 55 unit tests for `public/sicm2emmy.js` (the
Scheme→Emmy translator) via `node --test`. Always run before committing
translator changes.

Browser cycle (everything else):

1. Edit src/ or public/app.cljs.
2. `bb release` if src/ changed (plugin rebuild). Plain text changes to
   public/app.cljs need only a browser reload.
3. `bb serve` → http://localhost:1341 → manually evaluate snippets from
   the system pages (Welcome / SICM / Graphics / 3D).

## Known sharp edges (load-bearing knowledge)

- SCI's analyzer resolves symbols at analysis time. Forward references
  between defns in `public/app.cljs` need `(declare ...)`.
- emmy.env's `:refer :all` shadows `+ - * /`. Inside helpers like
  `animate` we fully-qualify `cljs.core/...` so timer arithmetic
  bypasses Emmy's generic dispatch (avoids ratio → BigInt overflow).
- mathbox 2.3.1 needs three.js pinned to 0.139.2 (its tested version);
  newer Three breaks primitive klass registration.
- emmy-viewers' high-level helpers return a quoted-form fragment; we
  detect `:portal.viewer/reagent?` metadata and re-eval to expand the
  `with-let` macro into actual hiccup.
- Reagent reactivity needs `@!atom` derefed in the render scope, not
  inside callbacks invoked later (the plot-with-params reactivity bug).
- Hiccup detection at the result-pane boundary uses `(or (keyword? h)
  (fn? h))` for the head; symbol heads are excluded so emmy-viewers'
  fragment data doesn't false-trigger a render.
- System pages are an `array-map` (insertion-ordered) keyed by name;
  copy-on-edit forks via content-identity check in the CM update listener.

## Git policy (overrides global)
You manage git directly in this project. The global "manual git" rule does
NOT apply here. `git push` remains denied at the permission layer; the user
handles pushing.

Workflow:
- Commit after each meaningful change passes its tests. One logical change
  per commit.
- Stage only the files relevant to the change. Use `git add <paths>`, not
  `git add .` or `git add -A`. Do not sweep up unrelated edits.
- Before committing, run `git diff --staged` and verify the diff is exactly
  what you intend. If something unintended is staged, `git restore --staged
  <path>` to unstage.
- Conventional commit messages: feat:, fix:, refactor:, docs:, test:, chore:.
  First line under 72 chars. Body if useful, omitted if not.
- Never commit on red. If a test was passing and now isn't, fix the test or
  the code before committing — do not commit broken state.
- Do not include AI attribution in commit messages.
